# TerraVoltec AI (Next.js + Ollama + Firebase + Stripe)

แชต AI แบบสมาชิก: ล็อกอิน ชำระรายเดือน โควตาต่อวัน และคอมมิชชั่นแนะนำ 6 ชั้น
คีย์ทุกตัวอยู่ฝั่งเซิร์ฟเวอร์ ผู้ใช้แก้สิทธิ์หรือยอดเงินจากเบราว์เซอร์ไม่ได้

## กติกาคอมมิชชั่น

เมื่อผู้ใช้จ่ายค่าบริการ ระบบหักก้อนคอมมิชชั่น (`pool_pct` ของยอดชำระ) แล้วแบ่งตามน้ำหนักของแต่ละชั้น
โดยปรับน้ำหนักรวมให้เป็น 100% ชั้น 1 ได้มากสุด ไล่ลงไปถึงชั้น 6

- ชั้นที่ไม่มีคนรับ (สายบนไม่ครบ 6 ชั้น) **ส่วนนั้นเข้าบริษัท** (เอกสารใน `commissionLedger` ที่ `beneficiaryId` เป็น null)
- เศษสตางค์จากการปัดลงตกที่ชั้น 1 เสมอ ผลรวมทุกชั้นจึงเท่ากับก้อนคอมมิชชั่นเป๊ะ
- คำนวณทั้งหมดที่เซิร์ฟเวอร์ใน Firestore transaction เดียว (`recordPayment` ใน `lib/store.ts`, สูตรอยู่ใน `lib/commission.ts`) ไม่ใช่ในเบราว์เซอร์
- จ่ายซ้ำไม่ได้: payment id เดิมถูกเรียกอีกกี่ครั้งก็ไม่สร้างแถวใหม่
- ยอดคอมมิชชั่นอยู่สถานะ `held` ตามจำนวนวัน `hold_days` ก่อนพร้อมจ่าย
- คืนเงินเต็มจำนวน: แถวที่ยังไม่จ่ายเป็น `reversed` แถวที่จ่ายไปแล้วเป็น `clawback` (ต้องเรียกคืนเอง) และสิทธิ์ใช้งานถูกตัดทันที

ตั้งค่าอัตราคอมมิชชั่นโดยสร้าง/แก้เอกสาร `settings/commission` ใน Firestore Console (ถ้าไม่มีเอกสาร ระบบใช้ค่าเริ่มต้นด้านล่าง
ถ้ามีแต่ค่าผิดรูปแบบ ระบบจะปฏิเสธการคิดเงินแทนที่จะคิดผิดเงียบ ๆ):

```
poolPct  (number)  30              ก้อนคอมมิชชั่น % ของยอดชำระ
weights  (array)   [10,8,6,4,2,1]  น้ำหนักชั้น 1..6 เป็นจำนวนเต็ม (ระบบปรับเป็น 100% เอง)
holdDays (number)  14              จำนวนวันที่ยอดอยู่สถานะ held
```

อัตราที่ใช้จริงของแต่ละรายการถูกบันทึกไว้ใน `commissionLedger.rateSnapshot` แก้อัตราทีหลังไม่กระทบรายการเก่า

## โครงข้อมูลใน Firestore

| คอลเลกชัน | เอกสาร | เนื้อหา |
|---|---|---|
| `users` | `{uid}` | อีเมล, แฮชรหัสผ่าน, `emailVerified`, `disabled`, `tokenVersion` |
| `emailIndex` | `{sha256(อีเมล)}` | อีเมล → uid (ประกันว่าอีเมลไม่ซ้ำ) |
| `authTokens` | `{sha256(โทเคน)}` | โทเคนยืนยันอีเมล/ตั้งรหัสใหม่ (เก็บเฉพาะแฮช มีวันหมดอายุ) |
| `loginAttempts` | `{sha256(อีเมล)}` | จำนวนครั้งที่ล็อกอินพลาด |
| `profiles` | `{uid}` | อีเมล, รหัสแนะนำ, ผู้แนะนำ, สายบน 6 ชั้น (`upline`), จำนวนสมาชิกแต่ละชั้น (`downline.l1..l6`), `paidUntil` |
| `referralCodes` | `{code}` | ดัชนีรหัสแนะนำ → uid (ประกันว่ารหัสไม่ซ้ำ) |
| `payments` | `{provider}_{paymentId}` | การชำระเงิน (id ซ้ำไม่ได้ = จ่ายซ้ำไม่ได้) |
| `commissionLedger` | `{provider}_{paymentId}_{level}` | สมุดบัญชีคอมมิชชั่น แถวละชั้น |
| `teamPv` | `{uid}_{YYYY-MM}` | PV ทีมของสมาชิกในเดือนนั้น (บวกเมื่อสายล่างจ่ายเงิน หักคืนเมื่อคืนเงิน) |
| `usageDaily` | `{uid}_{YYYY-MM-DD}` | จำนวนข้อความต่อวัน (นับตามเวลาไทย) |
| `settings` | `commission` | อัตราคอมมิชชั่น |

เบราว์เซอร์เข้า Firestore โดยตรงไม่ได้เลย (`firestore.rules` ปิดทั้งหมด) ทุกอย่างอ่าน/เขียนผ่านเซิร์ฟเวอร์ด้วย Admin SDK
ผู้แนะนำกำหนดตอนสร้างโปรไฟล์ครั้งเดียว ไม่มีโค้ดเส้นทางใดแก้ได้ภายหลัง

## การล็อกอิน

ระบบอีเมล + รหัสผ่านเป็นของตัวเอง เก็บใน Firestore ผ่าน Admin SDK **ไม่ใช้ Firebase Authentication และไม่ต้องตั้งค่า `NEXT_PUBLIC_FIREBASE_*`**
ต้องมีแค่ `FIREBASE_SERVICE_ACCOUNT` กับ Firestore Database

- รหัสผ่านเก็บเป็นแฮช scrypt (มี salt ต่อบัญชี) ไม่เก็บรหัสจริง ขั้นต่ำ 8 ตัวอักษร (`lib/security.ts`)
- เข้าสู่ระบบสำเร็จ = เซิร์ฟเวอร์ออกคุกกี้ `session` (httpOnly, อายุ 5 วัน) เซ็นลายเซ็น HMAC ด้วยกุญแจที่สร้างจาก service account (หรือ `SESSION_SECRET` ถ้าตั้งไว้)
  และตรวจกับฐานข้อมูลทุกคำขอ (`getSessionUser` ใน `lib/auth.ts`) ว่าบัญชีไม่ถูกพักและเซสชันไม่ถูกเพิกถอน
- ล็อกอินผิด 8 ครั้งต่ออีเมลภายใน 15 นาที = ล็อกชั่วคราว (ตอบข้อความเดียวกันไม่ว่าอีเมลมีบัญชีหรือไม่)
- เปลี่ยนรหัสผ่าน/พักบัญชี = เพิกถอนเซสชันเก่าทั้งหมดทันที
- รหัสแนะนำผูกตอนสมัครผ่าน `/api/auth/register`

**ระบบอีเมล (ไม่บังคับ แต่แนะนำ)** ตั้ง `RESEND_API_KEY` และ `MAIL_FROM` (ใช้ [Resend](https://resend.com) ต้องยืนยันโดเมนผู้ส่งก่อน)
- ตั้งแล้ว: สมัครแล้วต้องกดลิงก์ยืนยันอีเมลก่อนเข้าใช้งาน และมี "ลืมรหัสผ่าน?" ส่งลิงก์ตั้งรหัสใหม่ (ลิงก์ยืนยันอายุ 24 ชม. ลิงก์ตั้งรหัสใหม่อายุ 1 ชม. ใช้ได้ครั้งเดียว)
- ไม่ตั้ง: สมัครแล้วใช้งานได้ทันทีโดยไม่ยืนยันอีเมล และลืมรหัสผ่านทางอีเมลไม่ได้
  **ข้อควรระวัง:** แอดมินกำหนดจากอีเมลใน `ADMIN_EMAILS` ถ้าไม่เปิดระบบอีเมล ใครสมัครด้วยอีเมลแอดมินก่อนก็ได้สิทธิ์แอดมิน
  ให้เจ้าของสมัครด้วยอีเมลแอดมินทันทีหลังเปิดเว็บ (สมัครแล้วอีเมลนั้นถูกจองแล้ว) หรือเปิดระบบอีเมลก่อนใช้งานจริง

ผู้ใช้ที่เคยสมัครด้วย Firebase Authentication รุ่นก่อนหน้า ต้องสมัครใหม่ (บัญชีใหม่ไม่ผูกกับ uid เดิม)

## แอดมิน

กำหนดแอดมินด้วยตัวแปร `ADMIN_EMAILS` (คั่นอีเมลด้วยจุลภาค) แล้วล็อกอินด้วยบัญชีสมาชิกปกติ จะเห็นเมนู "แอดมิน" ไปที่ `/admin`
(ผู้ที่ไม่ใช่แอดมินเปิดหน้านี้จะเจอ 404) ตอนนี้ทำได้:
- ดูรายชื่อสมาชิกทั้งหมด (เรียงสมัครล่าสุด หน้าละ 50) ค้นหาด้วยอีเมล เห็นแพ็กเกจ ผู้แนะนำ และจำนวนที่แนะนำตรง
- พักบัญชี / ปลดพัก พร้อมเหตุผล: ปิดบัญชีและตัดเซสชันทันที ผู้ถูกพักล็อกอินไม่ได้
- พักตัวเองหรือแอดมินคนอื่นไม่ได้ ทุกการพัก/ปลดพักบันทึกลงคอลเลกชัน `adminLog`

ยอดคอมมิชชั่นของสมาชิกที่ถูกพักไม่ถูกแตะ (ยังสะสมและค้างสถานะตามเดิม) ให้แอดมินตัดสินใจเรื่องการจ่ายเอง

## ตั้งอัตราคอมมิชชั่นในหน้าแอดมิน

หน้า `/admin` มีฟอร์ม "อัตราคอมมิชชั่น" ให้กรอก 3 อย่าง:
- **จำนวนชั้น** ที่จ่าย 1-10 (ช่องกรอกเพิ่ม/ลดตามจำนวนชั้น)
- **คอมมิชชั่นแต่ละชั้น** เป็น % ของยอดชำระ (ทศนิยมได้ 2 ตำแหน่ง) เช่น ชั้น 1 = 10, ชั้น 2 = 5
- **จำนวนวันพักยอด** ก่อนพร้อมจ่าย (0-90)

**ผลรวมทุกชั้นต้องไม่เกิน 50% ของยอดชำระ** (ปรับที่ `ADMIN_LIMITS` ใน `lib/commission.ts`) ฟอร์มแสดงผลรวมสดและปิดปุ่มบันทึกถ้าเกิน
เซิร์ฟเวอร์ตรวจซ้ำ (`validateAdminSettings`) บันทึกลง `settings/commission` และเขียน `adminLog` เก็บค่าก่อน/หลังและผู้แก้
มีผลกับการชำระเงินครั้งถัดไปเท่านั้น รายการเก่าใช้อัตราใน `rateSnapshot` ของตัวเอง

### PV และยศ

ฟอร์มเดียวกันตั้งเรื่อง PV และยศได้ด้วย:
- **PV ต่อ 1 บาท**: ยอดชำระแปลงเป็น PV (ค่าเริ่มต้น 1 = ค่าบริการ 299 บาทได้ 299 PV)
- **ยศ** (สูงสุด 8): ชื่อยศ, PV ทีมขั้นต่ำ, และจำนวนชั้นที่ยศนั้นรับคอมมิชชั่นได้ ยศแรกคือยศเริ่มต้น (PV = 0)
- **ผู้รับต้องมีแพ็กเกจที่ยังไม่หมดอายุ**: ถ้าเปิด ผู้รับที่แพ็กเกจหมดอายุจะไม่ได้ส่วนนั้น

**PV ทีม** = PV ของค่าบริการที่สมาชิกในสายล่างของคุณจ่ายจริงในเดือนนั้น (เวลาไทย นับใหม่ทุกต้นเดือน) ไม่ได้นับยอดที่ตัวเองซื้อ
จึงไม่มีทางเลื่อนยศด้วยการซื้อเพิ่มเอง ยศคิดจากยอดรวมรวมการชำระครั้งที่กำลังคิดด้วย
ชั้นที่เกินกว่าที่ยศรับได้ หรือผู้รับที่แพ็กเกจหมดอายุ ส่วนนั้นเข้าบริษัท (บันทึก `reason` = `rank` / `inactive` และ `intendedBeneficiaryId` ไว้ในสมุดบัญชี)
ยศไม่เพิ่มเพดานรวม ผลรวมที่จ่ายต่อการชำระหนึ่งครั้งไม่เกินเปอร์เซ็นต์รวมที่ตั้งไว้เสมอ
เมื่อคืนเงิน ระบบหัก PV ทีมที่เคยนับจากรายการนั้นคืนด้วย (เฉพาะรายการที่สร้างหลังเพิ่มฟีเจอร์นี้)
สมาชิกเห็นยศ PV ทีม และ PV ที่ขาดถึงยศถัดไปในหน้าคอมมิชชั่น

**แสดงยอดคอมมิชชั่นเป็น PV**: ฟอร์มมีตัวเลือก "แสดงยอดคอมมิชชั่นให้สมาชิกเป็น" PV อย่างเดียว / PV และบาท / บาทอย่างเดียว (ค่าเริ่มต้น PV และบาท)
ใช้กับหน้าคอมมิชชั่นของสมาชิก แต่ละแถวในสมุดบัญชีเก็บ `pv` ตามอัตรา PV ต่อบาท ณ ตอนชำระ (แถวเก่าที่ไม่มี `pv` ใช้อัตราปัจจุบันคำนวณให้)
เป็นแค่การแสดงผล การจ่ายเงินจริงยังคิดเป็นสตางค์เสมอ

หมายเหตุเรื่องความลึกสาย: ระบบเก็บสายบนสูงสุด 10 ชั้น (`LEVELS`) สมาชิกที่สมัครก่อนปรับเป็น 10 ชั้นมีสายบนเก็บไว้แค่ 6 ชั้น
ชั้นที่ 7-10 ของพวกเขาจึงตกเป็นส่วนของบริษัทจนกว่าจะมีการย้ายข้อมูล (ถ้าเพิ่งเริ่มระบบ ไม่มีผลอะไร)

## ธีมสี (กลางวัน/กลางคืน)

ค่าเริ่มต้นคือโหมดกลางวัน (พื้นขาว) ทุกหน้ามีปุ่ม "กลางคืน/กลางวัน" สลับได้ จำค่าไว้ในเบราว์เซอร์ของผู้ใช้ (localStorage ชื่อ `theme`)
สีทั้งหมดอยู่ที่ตัวแปรใน `app/globals.css` (`:root` = กลางวัน, `:root[data-theme="dark"]` = กลางคืน) แก้ที่นั่นที่เดียว
สคริปต์เล็ก ๆ ใน `app/layout.tsx` ตั้งโหมดก่อนวาดหน้า จึงไม่เกิดหน้าขาวแวบ โลโก้สีไซยานโปร่งใสจะวางบนแผ่นสีกรมท่าในโหมดกลางวันเพื่อให้เห็นชัด

## ตั้งค่า

1. **Firebase (ใช้แค่ Firestore)**: สร้างโปรเจกต์ที่ console.firebase.google.com
   - Build > Firestore Database > Create database (โหมด production)
   - ติดตั้งกฎ: `firebase deploy --only firestore:rules` (หรือคัดลอกเนื้อหา `firestore.rules` วางที่แท็บ Rules)
   - Project settings > Service accounts > Generate new private key วางเนื้อไฟล์ JSON ทั้งก้อนในช่องเดียว `FIREBASE_SERVICE_ACCOUNT`
   - ไม่ต้องเปิด Authentication ไม่ต้องเพิ่ม Web app
2. **Stripe**: เปิด PromptPay ที่ Settings > Payment methods
   สร้าง Webhook endpoint ที่ `https://โดเมน/api/webhooks/stripe` ฟัง 3 อีเวนต์:
   `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `charge.refunded`
3. **โมเดล (Ollama)**: ติดตั้ง Ollama แล้ว `ollama pull gemma3:4b` (หรือโมเดลที่ต้องการ) จากนั้นตั้งตัวแปรฝั่งเซิร์ฟเวอร์
   - `OLLAMA_BASE_URL` ที่อยู่ Ollama ที่เซิร์ฟเวอร์ Next.js เรียกถึงได้ (ค่าเริ่มต้น `http://localhost:11434`)
   - `OLLAMA_MODEL` ชื่อโมเดลตาม `ollama list` (ค่าเริ่มต้น `gemma3:4b`)
   - `OLLAMA_API_KEY` ไม่บังคับ ใช้เมื่อมี reverse proxy คั่นหน้า Ollama
   ถ้าโฮสต์เว็บบน Vercel เซิร์ฟเวอร์จะเรียก `localhost` ของโน้ตบุ๊กคุณไม่ได้ ต้องให้ Ollama เข้าถึงได้ผ่านช่องทางที่ปลอดภัย (เช่น Cloudflare Tunnel + รหัสผ่านที่ proxy)
   หรือรัน Next.js บนเครื่องเดียวกับ Ollama แล้วเปิดเว็บผ่าน Tunnel แทน
   ห้ามเปิดพอร์ต 11434 ออกอินเทอร์เน็ตตรง ๆ เพราะ Ollama ไม่มีระบบยืนยันตัวตน
4. คัดลอก `.env.example` เป็น `.env.local` ใส่ค่าให้ครบ (บน Vercel ใส่ใน Environment Variables)
5. ราคาและโควตาแก้ที่ `lib/config.ts`

```bash
npm install
npm run dev
```

ทดสอบ webhook บนเครื่อง: `stripe listen --forward-to localhost:3000/api/webhooks/stripe`
แล้วนำ `whsec_...` ที่ได้ไปใส่ใน `STRIPE_WEBHOOK_SECRET`

## ยังไม่มี (ต้องทำก่อนจ่ายเงินจริง)

- **การจ่ายเงินออกให้สมาชิก** ตอนนี้เปลี่ยนสถานะเป็น `paid` เองใน Firestore Console (`status = "paid"`, `paidAt` = เวลาปัจจุบัน)
  ควรมีหน้าแอดมิน การยืนยันตัวตน (KYC) ข้อมูลบัญชีรับเงิน และการหักภาษี ณ ที่จ่าย
- Rate limit ต่อ IP นอกเหนือจากโควตาข้อความรายวัน
- ใบเสร็จ/ใบกำกับภาษี

## เรื่องกฎหมาย

คอมมิชชั่นมาจากค่าบริการที่ผู้ใช้จ่ายและใช้งานจริงเท่านั้น ไม่มีค่าสมัครหรือค่าซื้อตำแหน่ง
